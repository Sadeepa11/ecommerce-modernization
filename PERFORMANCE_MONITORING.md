# TechMart Online E-Commerce — Performance Measurement & Monitoring Setup Guide

This document details how to execute load tests and monitor the performance, thread pools, and concurrency profiles of the modernized TechMart Online E-Commerce application.

---

## 📊 1. Load Testing Setup (Apache JMeter)

The repository contains a pre-configured JMeter test plan named [techmart_perf_test.jmx](file:///C:/Users/97150/Desktop/ecommerce-modernization/techmart_perf_test.jmx).

### Load Test Specifications:
- **Concurrent Users (Threads)**: `100` threads simulating simultaneous shoppers.
- **Ramp-Up Period**: `10` seconds (threads will start gradually over 10 seconds).
- **Loops per Thread**: `100` repetitions.
- **Total Requests**: `10,000` total operations.
- **HTTP Transactions Executed**:
  1. `GET /ecommerce-modernization/api/products` (Retrieves products catalog)
  2. `POST /ecommerce-modernization/api/orders/demo` (Submits a checkout request, firing the Order Producer, JMS Queue, MDB order consumer, and inventory stock deduct logic)
  3. `GET /ecommerce-modernization/api/metrics` (Retrieves live EJB performance telemetry logs and counts)

---

### How to Run the Performance Test

#### Method A: Automated CLI Mode (Recommended)
1. Open PowerShell in the project root folder.
2. Run the provided helper script:
   ```powershell
   .\run_perf_test.ps1
   ```
   *Note: If the `jmeter` command is not in your PATH, the script will prompt you to enter the absolute path to your `jmeter.bat` file.*
3. Open the generated `perf_report_html/index.html` file in any web browser to view the interactive performance graphs (Response Time Percentiles, Throughput TPS, Error Rates, etc.).

#### Method B: Interactive GUI Mode
1. Open Apache JMeter.
2. Click **File -> Open** and select [techmart_perf_test.jmx](file:///C:/Users/97150/Desktop/ecommerce-modernization/techmart_perf_test.jmx).
3. Use the GUI test controls to run the tests and examine live reports using the built-in listeners:
   - **Summary Report**: Displays average response times, min/max latency, and error percentages.
   - **View Results Tree**: Displays raw HTTP request and response payloads for debugging.
   - **Graph Results**: Plots response times over the duration of the test.

## 📈 2. Server-Side Monitoring Setup (Payara & EJB Container)

To measure how the application server handles the concurrent load during testing, monitor the following components:

### A. Live EJB Telemetry Endpoint (Metrics Registry)
The application captures method execution counts and average response times directly in the `@Singleton` registry bean. You can view these metrics in real-time under load:
1. Open a browser or run a GET request to:
   👉 **[http://localhost:8080/ecommerce-modernization/api/metrics](http://localhost:8080/ecommerce-modernization/api/metrics)**
2. The endpoint returns JSON telemetry containing:
   - **Active Sessions**: Number of active Stateful Session Beans (`ShoppingCartSession`).
   - **Requests Handled**: Total requests routed through the WAR controller.
   - **JMS Orders Processed**: Counts of successful and failed orders consumed by `OrderProcessorMDB`.
   - **EJB Latency Benchmarks**:
     - Average stock-check duration (using `@Lock(LockType.READ)` read concurrency).
     - Average cart update duration.
     - Average checkout processing duration.
   - **System Event Logs**: The last 30 log lines generated by EJB concurrency events (e.g., asynchronous task completions, queue consumer messages).

### B. Payara Server Connection and Thread Pools
To monitor low-level Payara JVM threads, HTTP server execution, and JTA connection pools:
1. Go to the Payara Admin Console: **[http://localhost:4848/](http://localhost:4848/)**
2. **Thread Pools**:
   - Go to **Configurations -> server-config -> Thread Pools**.
   - Monitor the active usage of `http-thread-pool` (limited to `200` concurrent threads) and `thread-pool-1` (ORB thread pool).
3. **Request Tracing**:
   - Go to **Configurations -> server-config -> Request Tracing**.
   - Enable request tracing and set the threshold to monitor slow operations (e.g., transactions taking > 1000ms).
4. **JMS Engine Monitoring**:
   - Go to **Configurations -> server-config -> Java Message Service**.
   - Monitor active JMS connections and MDB consumer thread distributions.
